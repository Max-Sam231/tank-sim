Симулятор кабины механика-водителя (Driver Sim)
📋 Описание проекта
Интерактивное учебное пособие, разработанное для обучения курсантов военного учебного центра (ВУЦ) алгоритму запуска двигателя и эксплуатации систем танка. Программа имитирует рабочее место механика-водителя и позволяет отрабатывать последовательность действий в безопасной цифровой среде.

🎯 Основные цели
Обучение: Отработка правильной последовательности включения систем (масса, топливо, масло, запуск).

Тренировка: Закрепление навыков взаимодействия с органами управления в виртуальной кабине.

Контроль: Проверка знаний курсанта в режиме «Экзамен» с фиксацией ошибок.

💻 Технические характеристики
Проект разработан с учетом работы на маломощных персональных компьютерах (учебные классы, старые ноутбуки).

Стек: Ванильный JavaScript (ES6+), HTML5, CSS3.

Производительность: Нулевая зависимость от тяжелых фреймворков и библиотек. Запускается в любом современном браузере.

Графика: Статическая 2D-растровый фон с наложенным слоем интерактивных SVG-элементов.

🛠 Архитектурные особенности
State Machine (Машина состояний): Логика запуска двигателя реализована через строгое управление состоянием систем. Двигатель не запустится, если не выполнены предварительные условия (например, не выжата педаль или не включена масса).

SVG Hitboxes: Для взаимодействия с объектами в перспективе (рычаги, кнопки под углом) используются невидимые векторные маски, обеспечивающие точный клик.

Модульность:

Instruction: Теоретический блок с описанием узлов.

Training: Свободное взаимодействие с подсказками по алгоритму.

Exam: Тестирование на время и точность без визуальной помощи.

## Как запустить

### Вариант 1 (рекомендуется): dev-сервер + авто-перезагрузка

1. Установить Node.js.
2. Установить зависимости.
3. Запустить dev.

```bash
npm install
npm run dev
```

После запуска:

- **UI**: http://localhost:8000
- **Live reload (WS)**: ws://localhost:8001

### Вариант 2: простой статический сервер (без live reload)

```bash
npm install
npm run serve
```

Открой:

- **UI**: http://localhost:8000

### Вариант 3: открыть `index.html` как файл

Не рекомендуется, потому что браузеры часто блокируют ES-модули (`<script type="module">`) и загрузку ресурсов по `file://`. Если очень нужно — используйте любой локальный HTTP-сервер.

---

## Требования

- **Node.js**: нужен только для запуска локального сервера и live-reload.
- **Браузер**: любой современный (Chrome/Edge/Firefox).

## Структура проекта (что за что отвечает)

### Корень

- **`index.html`**
  Главная разметка симулятора.
  Содержит:
  - фон сцены (`.scene`) с растровой картинкой кабины,
  - SVG-слой с `polygon.hitbox` (кликабельные области) и `data-action`,
  - модалку "приборной панели" (второй SVG-слой hitbox’ов),
  - `#debugConsole` (текущий снимок состояния),
  - модалку требования полноэкранного режима.

- **`styles.css`**
  Стили и слои (фон, hitbox-layer, overlay-layer), режим отладки hitbox’ов, модалки.

- **`main.js`**
  Точка входа.
  Создаёт `TankState`, подключает `UIController`, настраивает `FullscreenManager`.

- **`package.json`**
  Скрипты разработки:
  - `dev`: `serve` + `live-reload-server.js` параллельно
  - `serve`: раздача статики на 8000

- **`live-reload-server.js`**
  WebSocket-сервер (порт 8001), следит за изменениями файлов (`.html/.css/.js` и картинки в `img/`) и отправляет клиентам команду `reload`.

- **`live-reload.js`**
  Клиентская часть live-reload: подключается к `ws://localhost:8001`, при сообщении `reload` перезагружает страницу.

### Папка `js/`

- **`js/TankState.js`**
  Централизованное состояние симулятора.
  Хранит значения органов управления и предоставляет методы изменения (toggle/cycle/set).
  Важное:
  - `subscribe(listener)` — подписка на изменения;
  - `_emit()` — рассылает подписчикам snapshot (`getSnapshot()`).

- **`js/UIController.js`**
  Связывает DOM и `TankState`.
  Делает 3 основные вещи:
  - слушает клики/нажатия по `.hitbox` и `.overlay-control`,
  - вызывает методы `TankState` по `data-action`,
  - перерисовывает UI по snapshot: overlays и debug-консоль.

  Дополнительно:
  - создаёт подписи hitbox’ов (в SVG) и переключает видимость hitbox’ов по клавише `H`.

- **`js/ControlOverlayDefs.js`**
  Таблица соответствий `data-action` -> визуальный overlay.
  Определяет тип управления:
  - `boolean` (on/off),
  - `enum` (несколько позиций),
  - `range` (диапазон, выбирается ближайший кадр).
    Здесь же задаются картинки (`src`) и подгонка (`inflate/offsetX/offsetY/z`).

- **`js/FullscreenManager.js`**
  Управление полноэкранным режимом и модалкой.
  Также вешает обработчик "Назад" для закрытия приборной панели.

### Папка `img/`

- **`img/`**
  Все графические ассеты.
  В частности:
  - `фон.jpg` — фон кабины,
  - `Прибор фон.png` — фон приборной панели,
  - подпапки `1/..12/` — кадры/состояния для overlay-элементов.

## Общая логика (коротко)

Данные идут в одном направлении:

1. Пользователь кликает по `polygon.hitbox` (SVG) или по `img.overlay-control`.
2. `UIController` читает `data-action` и вызывает соответствующий метод в `TankState`.
3. `TankState` меняет значение и вызывает `_emit()`.
4. Подписчик в `UIController` получает snapshot и:
   - обновляет overlays (картинки поверх фона) по `ControlOverlayDefs`,
   - обновляет `#debugConsole`.

Ключевой инвариант: `TankState` не знает про DOM, а UI обновляется только из snapshot.

---

## Как добавлять новый орган управления

1. В `index.html` добавить новый `polygon.hitbox` с `data-action="..."`.
2. В `js/TankState.js` добавить поле состояния + метод изменения.
3. В `js/UIController.js` добавить обработку `case` для этого `data-action`.
4. (Опционально) В `js/ControlOverlayDefs.js` добавить определение overlay, чтобы отображать разные кадры/положения.
