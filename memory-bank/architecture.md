# Архитектура системы

## Принципы архитектуры

1. **Separation of Concerns** — UI-логика отделена от бизнес-логики и физики (состояния).
2. **Centralized State** — единый источник истины (`TankState`).
3. **Reactive Updates** — UI, звуки и визуальные эффекты обновляются по подписке на изменения состояния.
4. **Data-driven** — поведение приборов и оверлеев определяется конфигурацией, а не жестким кодированием.

## Игровой цикл

В `main.js` работает постоянный игровой цикл через `requestAnimationFrame`:

```javascript
const loop = (ts) => {
  if (!isLoopRunning) return;
  const dt = Math.max(0, (ts - lastTs) / 1000);
  lastTs = ts;

  state.tick(dt);         // Обновление физических процессов танка
  sceneManager.update(dt); // Обновление активной сцены (анимации, хитбоксы)

  rafId = requestAnimationFrame(loop);
};
```

- **state.tick(dt)** — выполняет шаг интеграции физики. Ограничивает шаг `dt = Math.min(dt, 0.25)`.
- **sceneManager.update(dt)** — передает шаг текущей активной сцене для внутренней динамики.

## Система сцен и видов

```
SceneManager
    │
    ├── HangarScene (scene-hangar)
    │       ├── TankTopView (Вид сверху)
    │       │     └── Люки → переход в DriverScene / CommanderScene
    │       │     └── Ящик ЗИП → переход в ZipBoxScene
    │       ├── TankSideView (Вид сбоку слева)
    │       │     └── Обогрев → переход в HeaterScene
    │       └── TankSideRightView (Вид сбоку справа)
    │
    ├── DriverScene (scene-driver)
    │       └── Основная симуляция кабины механика-водителя
    │       └── Модальные окна (БЦН, Жалюзи, КПП, Ручная подача)
    │       └── Детальная Приборная панель (модальное окно)
    │
    ├── CommanderScene (scene-commander)
    │       └── Прямой вид / Наклонный вид (straight/tilted)
    │       └── Рычаг подачи топлива на обогреватель (вкл/выкл)
    │
    ├── HeaterScene (scene-heater) [загружается как null-сцена в SceneManager]
    │       └── Открытие бортов, откручивание болтов, установка козырька
    │
    └── ZipBoxScene (scene-zip-box) [загружается как null-сцена в SceneManager]
            └── Забор инструментов (ключ, козырёк выхлопа)
```

**Жизненный цикл сцены:**
1. `init()` — инициализация обработчиков, отображение кнопок (например, "Закончить").
2. `update(dt)` — покадровая логика.
3. `dispose()` — удаление глобальных обработчиков, очистка DOM, скрытие кнопок.

## Система хитбоксов

Используется SVG-слой, наложенный поверх растрового фона:
- `preserveAspectRatio="xMidYMid meet"` обеспечивает корректное масштабирование хитбоксов вместе с фоном без искажения пропорций (в отличие от `none`, которое может приводить к смещениям на экранах с разным соотношением сторон).
- Каждая интерактивная область задается полигоном `<polygon class="hitbox" points="..." data-action="..." />`.
- `data-action` сопоставляется с обработчиками кликов в `UIController` или сценах.

## Система оверлеев и стрелок приборов

Визуальное отображение состояний привязано к описаниям в `ControlOverlayDefs.js`:
1. **Динамические переключатели (Boolean, Enum, Range)**:
   - `UIController` создает элементы `<img>` и позиционирует их в процентах относительно размеров viewBox (1920×1080).
   - В зависимости от состояния в `TankState` меняется атрибут `src` (спрайт оверлея).
2. **Стрелочные приборы (Gauge)**:
   - Не используют полигоны для каждого положения.
   - Отрисовываются с помощью отдельного спрайта стрелки, накладываемого на прибор.
   - Угол поворота рассчитывается в `UIController._updateGaugeArrows(snapshot)` на основе диапазона сенсора (`min` / `max` / `zeroOffset` для асимметричной шкалы ВА-540) и углового диапазона (`startAngle` / `endAngle`).
   - Поворот осуществляется через CSS-свойство `transform: rotate(var(--rot))` с точкой вращения `transform-origin: var(--pivot-x) var(--pivot-y)`.

## Система подписок и реактивности

Для разделения логики `TankState` не знает об существовании `UIController`, `AudioManager` или `ExhaustSmoke`. Вместо этого он предоставляет метод подписки:
```javascript
subscribe(listener) {
  this._listeners.add(listener);
  return () => this._listeners.delete(listener);
}
```
Любое изменение внутреннего состояния в `TankState` (или прохождение шага `tick`) вызывает приватный метод `_emit()`, рассылающий копию состояния (Snapshot) всем подписчикам.
